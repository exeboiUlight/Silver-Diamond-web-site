Silver Diamond Game Engine

Документация публичного API · C99 · OpenGL 3.3+

Обзор

Silver Diamond Game Engine — небольшой переносимый 2D/3D-движок на C99. API плоский: почти всё — свободные функции с префиксом модуля. Точка входа для игрового кода — #include "sdge.h".

Соглашения

ПрефиксМодуль
sdge_Ядро: окно, сцены, камеры, модели, свет
sdgr_Рендерер (forward, PBR-lite)
sdga_Ассеты: арена, WAV/MP3, шрифты, glTF
sdui_Низкоуровневый 2D UI (батчинг)
sdg_Математика (header-only)
sdph2_ / sdph3_2D/3D физика
sdj_JSON-сканер (header-only)

Матрицы и координаты

Все матрицы — column-major float[16], индекс = col*4 + row. Правосторонняя система, −Z вперёд, +Y вверх (как в glTF). Загрузка в GL: glUniformMatrix4fv(..., GL_FALSE, m).

Типовой кадр 3D

#include "sdge.h"

sdge_window *w = sdge_create_window(1280,720,"Demo",NULL);
sdge_make_context_current(w);
sdgr_init();
sdui_init();

sdge_camera3d cam; sdge_camera3d_init(&cam, 60.0f, 16.0f/9.0f, 0.1f, 100.0f);
sdge_camera3d_orbit(&cam, (float[]){0,0,0}, 5.0f, 0.6f, 0.4f);

sdge_model *m = sdge_model_load("assets/character.glb");
sdge_model_play(m, 0, 1);

sdge_gui *gui = sdge_gui_create();
/* ... кнопки, лейблы ... */

while (!sdge_window_should_close(w)) {
    sdge_poll_events();
    sdge_camera3d_update(&cam);
    sdgr_resize(1280,720);
    sdgr_begin_frame(NULL);
    sdgr_set_camera(cam.view, cam.proj, cam.pos);
    sdgr_set_ambient(0.25f,0.25f,0.3f);
    sdgr_set_sun((float[]){-0.5f,-1.0f,-0.3f}, (float[]){1,1,1}, 2.0f);
    sdge_model_advance(m, 1.0f/60.0f);
    sdge_model_draw(m, NULL);
    sdge_gui_begin(gui, 1280, 720);
    sdge_gui_draw(gui);
    sdge_gui_end(gui);
    sdgr_end_frame();
    sdge_swap_buffers(w);
}
Приложение не включает GL-заголовки — glad загружается внутри sdgr_init().

sdge_def.hH ~30 строк

Назначение: общие defines, от которых зависят все остальные заголовки.

  • SDGE_API — экспортный макрос (dllexport/dllimport/visibility("default")/пусто).
  • SDGE_INLINE = static inline — для header-only хелперов.
  • SDGE_VERSION_STRING — строка версии.
  • Подключает <stdint.h>, <stddef.h> (нужны int64_t, size_t, uint64_t в окне и т.п.).

Связи: подключается первым во всех публичных заголовках. Приложение выбирает режим сборки через -DSDGE_BUILD_DLL / -DSDGE_USE_DLL.

sdge.hH ~70 строк

Назначение: umbrella-header — единственный include для игрового кода.

  • Включает sdge_def.h + все публичные заголовки модулей.
  • Порядок включения важен: window.h инстанцируется в window.c, но подключается первым.
  • Ничего не определяет сам — только агрегирует.

Связи: статическая сборка = скомпилировать все .c движка (список в core/config.py). DLL-сборка = window.c, mesh.c, renderer.c, ui.c, assets.c, gltf.c, font.c, font_cff.c, mp3.c, anim.c, audio.c, physics2d.c, physics3d.c, scene.c, Camera.c (2D и 3D), model.c, light-.c, GUI-.c.

graphics/window.hHO ~700 строк

Назначение: header-only платформенный слой — окно и GL-контекст, API в стиле GLFW.

  • Публичная часть: типы sdge_window, sdge_monitor, enum sdge_key, sdge_mouse_button, sdge_action, sdge_hint; API создания/уничтожения окна, событий, колбэков, ввода, таймеров.
  • Реализация под #ifdef SDGE_WINDOW_IMPLEMENTATION:
    • Windows: windows.h, windowsx.h, WGL — создание класса окна, WndProc, колбэки через WM_KEYDOWN и т.д.
    • Linux: X11/Xlib.h, XKBlib.h, GLX — выбор visual, XCreateWindow, glXMakeCurrent.
    • Строки sdge__strdup — своя реализация (MinGW.org не имеет strdup).
    • Колбэк-диспетчеризация, сброс клавиш при потере фокуса, fullscreen через _NET_WM_STATE/SetWindowPos.
    • Ключи транслируются в sdge_key: sdge__win_vk_to_key, sdge__x11_keycode_to_key.
    • Таймеры: QueryPerformanceCounter / clock_gettime(CLOCK_MONOTONIC).
  • SDGE_NO_GL отключает весь GL-путь.
  • Ограничение: только Windows + Linux/X11, без Wayland; ОС должна сама решать, какой бэкенд.

Связи: другие модули не включают GL-заголовки; только window.h и TU, собираемые с glad (mesh.c, renderer.c, ui.c). Приложение зовёт sdge_make_context_current() перед sdgr_init().

graphics/window.cIMPL ~5 строк

Назначение: «инстанцирующий» TU для header-only window.h.

#define SDGE_WINDOW_IMPLEMENTATION
#include "window.h"

Связи: должен быть скомпилирован ровно один раз в DLL/статической сборке.

graphics/mesh.hH ~60 строк

Назначение: публичный интерфейс GPU-меша.

  • sdge_mesh — VAO/VBO/EBO, флаги, bounding sphere.
  • Функции: sdge_mesh_upload, sdge_mesh_create_box, sdge_mesh_create_sphere, sdge_mesh_destroy, sdge_mesh_world_sphere.
  • Комментарий фиксирует конвенцию скиннинг-атрибутов: интерливинг (joint, weight)×4 float32.

Связи: включает assets/gltf.h (нужен sdge_primitive).

graphics/mesh.cC ~330 строк

Назначение: загрузка glTF-примитива в GL-объекты и создание процедурных мешей.

  • m_to_f32 — конверсия любого accessor'а в float32 один раз (или NULL для zero-copy float). Обрабатывает normalized и non-normalized целые типы.
  • m_upload_attrib — генерирует VBO, заливает данные, ставит glVertexAttribPointer.
  • sdge_mesh_upload — главная: upload POSITION/NORMAL, сборка скиннинг-буфера (интерлив + ре-нормализация весов), upload индексов (u16/u32 напрямую, u8 конвертируется), подсчёт bounding sphere (min/max из accessor или скан данных).
  • mesh_upload_raw — упрощённый путь для процедурных мешей: позиции + нормали + индексы u16, один interleaved layout (stride 24).
  • sdge_mesh_create_box — 6 граней × 4 вершины, правильная намотка для negative-sign граней.
  • sdge_mesh_create_sphere — UV-сфера: slices/stacks, координаты и нормали.
  • sdge_mesh_world_sphere — трансформация центра и умножение радиуса на max длину столбца матрицы (масштаб).
  • SDGE_NO_GL: заглушки (upload → −1, destroy/world_sphere пустые).

Связи: использует math/math3d.h (через mesh.h), assets/gltf.h (типы accessor/primitive), glad. Вызывается из subjects/3D/model.c.

graphics/renderer.hH ~80 строк

Назначение: публичный интерфейс forward-рендерера.

  • Константы: SDGR_MAX_POINT_LIGHTS (8), SDGR_MAX_JOINTS (128).
  • Функции: sdgr_init/shutdown, resize, begin_frame/end_frame, set_camera, sphere_visible, свет (ambient/sun/point_light), draw_mesh, screenshot.
  • Комментарий фиксирует: glad — private-зависимость, приложение GL-заголовков не видит.

Связи: включает math3d.h, mesh.h.

graphics/renderer.cC ~430 строк

Назначение: единственный шейдер на всё + внутреннее состояние + draw.

  • R_VS / R_FS — встроенные GLSL 330: skinning в VS (матрица от joint'ов), PBR-lite в FS (GGX + diffuse + ambient). Point lights до 8.
  • r_state — кэш uniform-локаций, камера, frustum, point lights. Один глобальный g_r.
  • r_compile — компиляция шейдера с логом в stderr.
  • sdgr_init — glad, компиляция, линковка, кэш локаций, установка дефолтов после g_r_inited = 1 (иначе сеттеры не работают — старый баг зафиксирован в комментарии).
  • sdgr_set_camera — копия view/proj, вычисление frustum из VP.
  • sdgr_draw_mesh — загрузка uniforms, VAO bind, glDrawElements/glDrawArrays, ловля первой GL-ошибки, отключение/включение cull для double-sided.
  • sdgr_screenshot — PPM (P6), читает back buffer построчно и пишет снизу-вверх (инверсия).
  • SDGE_NO_GL: заглушки.

Связи: единственный TU (вместе с mesh.c, ui.c), который тянет glad/glad.h; вызывается из subjects/3D/model.c, light-обёрток и приложения.

graphics/ui.hH ~110 строк

Назначение: публичный интерфейс шейдерного 2D UI.

  • sdui_rect — структура прямоугольника (position, size, radius, border, softness, mode, цвета).
  • SDUI_MODE_BOX/TEXT/SOFT.
  • Функции: init/shutdown, set_font/get_font, begin/end/quad_count, draw_rect, box, text*.
  • Константы SDUI_FONT_W/H = 5/7 (для расчёта ширины встроенного шрифта).

Связи: включает assets/font.h.

graphics/ui.cC ~560 строк

Назначение: SDF-шейдер, батчинг, работа с атласом шрифта.

  • UI_VS / UI_FS — позиция + UV + fill + border + shape + local. FS: sdRoundBox SDF, режимы box/text/soft.
  • ui_state g_ui — программа, VAO/VBO, атлас, staging-буфер вершин, шрифт (current + builtin), proj-матрица, размер.
  • ui_upload_atlas / ui_apply_font — заливка A8-текстуры в GL, переключение шрифта.
  • ui_push_quad — заполняет 20 float на вершину (pos, uv, color, border, shape, local), растит verts.
  • sdui_init — компилирует шейдер, создаёт VAO/VBO 2048*20 floats, встроенный шрифт. sdui_set_font меняет текущий.
  • sdui_begin — устанавливает pixel-space ортопроекцию (origin top-left, y down), blend, depth off.
  • sdui_end — заливка VBO и один glDrawArrays.
  • sdui_text — пен по глифам, масштаб k = size/native, ближайший face, перенос строки через \n.
  • sdui_text_width/height — advance-сумма и line-height.
  • SDGE_NO_GL: заглушки.

Связи: glad, assets/font.h. Используется из subjects/2D/gui/* и scene/scene.c.

math/math3d.hHO ~350 строк

Назначение: вся 3D-математика (header-only). static inline — нулевая стоимость подключения.

  • Типы: sdg_vec3, sdg_vec4, sdg_quat, sdg_mat4.
  • Vec3/4: add/sub/mul/dot/cross/len/norm/lerp.
  • Quat: identity, axis-angle, mul, slerp, rot_vec3, to_mat4.
  • Mat4: mul, translation, scaling, mul_point/mul_vec4/mul_vec3_dir, transpose, invert (Cramer), invert_rigid, perspective, ortho, look_at, from_trs.
  • Frustum: frustum_from_vp (6 inward), sphere_in_frustum.

Связи: подключается почти всеми модулями. Замечание: Cramer-инверсия — дорогая, но редкая.

assets/assets.hHO ~360 строк с реализацией

Назначение: chunked arena + файлы + WAV. Реализация живёт в том же заголовке под #ifdef SDGE_ASSETS_IMPLEMENTATION.

  • Арена: связанный список блоков, каждый — malloc'ed и не двигается. sdga_alloc_aligned при переполнении добавляет новый блок (удвоение) и ставит его в голову. Указатели стабильны на всю жизнь арены.
  • sdga_read_file — whole-file slurp, возвращает malloc'd буфер.
  • sdga_load_wav — RIFF/WAVE: идёт по chunks, читает fmt и data, поддерживает PCM u8/s16/s24/s32, IEEE float32, WAVE_FORMAT_EXTENSIBLE. Пропускает word-align паддинг. Конвертирует в interleaved float32 [−1,1].
  • sdga_free_wav — free samples.

Связи: используется gltf.h (арена — модель), font.c (чтение файла), mp3.c, audio.c (WAV для микшера).

assets/assets.cIMPL ~4 строки

Назначение: инстанцирует SDGE_ASSETS_IMPLEMENTATION.

Связи: один раз в DLL/static сборке.

assets/gltf.hHO ~1050 строк (включая реализацию)

Назначение: загрузчик glTF 2.0 (.glb / .gltf + .bin). Модель — одна арена.

  • Публичные типы: sdge_accessor, sdge_primitive, sdge_gltf_mesh, sdge_gltf_node, sdge_gltf_skin, sdge_gltf_channel, sdge_gltf_animation, sdge_gltf_material, sdge_gltf_model.
  • sdge_load_gltf — читает GLB (12-байтный заголовок + JSON/BIN chunks) или .gltf+bin (внешний uri). Резолвит nodes (matrix или TRS), scene roots, meshes, primitives, skins (IBM), animations (каналы + samplers), materials (PBR-факторы).
  • Zero-copy: accessor'ы указывают прямо в BIN chunk. Конверсия в float32 (для анимаций/IBM) — один раз через g_accessor_to_f32.
  • g_parse_accessor — учитывает bufferView/byteOffset/byteStride/componentType/type/normalized/min/max. Проверяет выход за границы буфера.
  • g_load_buffer0 — для .gltf: URI относительно каталога файла, чтение, копирование в арену.
  • Отсутствующие компоненты ноды берут дефолты из спеки (translation=0, rotation=identity, scale=1) — старый баг с нулевым масштабом исправлен.
  • sdge_gltf_destroy — одна sdga_arena_destroy + free модели.
  • Не поддержано: morph targets, sparse accessors, Draco, base64-URI, текстуры.

Связи: включает math3d.h, assets.h, json.h (реализация). Используется mesh.c (upload примитива), subjects/3D/model.c (высокоуровневая модель), anim.c (каналы).

assets/gltf.cIMPL ~5 строк

Назначение: инстанцирует SDGE_GLTF_IMPLEMENTATION.

assets/json.hHO ~200 строк

Назначение: token-based JSON-сканер в стиле jsmn. Zero-alloc, токены — срезы в исходном тексте.

  • Тип sdj_token: type, start/end (смещения в src), size (прямые дети), parent (индекс контейнера).
  • sdj_parse — единый проход, стек контейнеров, примитивы до разделителя, строки с escape-обработкой.
  • Навигация: sdj_obj_get (по ключу), sdj_arr_at (по индексу), sdj_subtree_tokens (размер поддерева), sdj_len, sdj_num, sdj_str.
  • MAX_TOKENS = 4096 — фиксированный размер; при превышении парсинг вернёт −1.
  • Комментарий фиксирует семантику size: для объекта — 2 × число пар (ключ + значение), для массива — число элементов.

Связи: используется только gltf.h (реализация).

assets/font.hH ~90 строк

Назначение: публичный API шрифтов.

  • sdga_glyph — размеры, bearings, advance, UV.
  • sdga_font — opaque.
  • Загрузка: sdga_load_font(path, size), sdga_load_builtin_font(size), sdga_free_font.
  • Faces: sdga_font_add_face, face_count, face_size, face_for, face_glyph.
  • Метрики: ascent, descent, line_height, glyph_index, glyph, glyph_count.
  • Атлас: pixels, texture_size, name.
assets/font.cC ~850 строк

Назначение: парсер sfnt + растеризатор TrueType + атлас + встроенный шрифт.

  • sdga_pen — outline sink: список сегментов (x0,y0,x1,y1) в пиксельном пространстве. move/line/quad/cubic/close.
  • rasterize — scanline с 5 subsamples на строку. Для каждой подстроки: сортирует пересечения по x, заливает пары (even-odd). Оптимизация: span_add с частичными пикселями.
  • sfnt: find_table, cmap_subtable (выбирает лучший unicode-подтайл: 3/10 формат 12, 3/1 формат 4, symbol), cmap_lookup (0/4/6/12).
  • TrueType glyf: glyf_simple (разжимает флаги, координаты, собирает контуры, учитывает два off-curve подряд через mid-point), glyf_composite (пока поддерживает только ARGS_ARE_XY_VALUES — трансформации пока игнорируются).
  • CFF: в font_cff.c.
  • Атлас: shared shelf-packer. atlas_place кладёт битмап, atlas_grow удваивает и пересчитывает UV через atlas_refresh_uvs.
  • build_face — для codepoints 32..255: растеризует, вычисляет advance из hmtx, кладёт в атлас.

physics/physics2d.cC ~560 строк

Назначение: реализация 2D-физики.

  • Broadphase cache (ph2_cache): массив AABB (4 float/body), порядок, буфер контактов. Переиспользуется — нет malloc в step.
  • body_aabb — AABB для circle/box (с учётом поворота).
  • collide_circle / collide_circle_box / collide_box — narrow phase. Box-box через SAT по 4 осям (2 на каждый box), contact point — самая глубокая вершина.
  • prepare_contact — эффективные массы по нормали и касательной, restitution (min), friction (sqrt), начальная vn_init, bias.
  • solve_contact — sequential impulses, restitution только при vn_init < −1, friction clamp по нормали.
  • sdph2_step — интеграция, broadphase (sort by minx, sweep, Y-overlap), narrow phase (contacts до 512), solver (iterations), positional correction, bounds, sleep (v² < 0.25, |ω| < 0.6, 0.4 c).
  • Мелочь В sdph2_energy ошибка приоритета оператора (работает случайно).
  • Замечание: в отличие от 3D, здесь нет накопления импульсов (normal_accum/tangent_accum), что делает 2D-стопки менее стабильными.

physics/physics3d.cC ~800 строк

Назначение: реализация 3D-физики с SAT-15 и манифолдами.

  • Константы: SDPH3_MAX_SPEED=30, MAX_ANGVEL=25, SLOP=0.01, MAX_BIAS=0.6, MAX_CONTACTS3=512.
  • body_basis — матрица 3×3 из эйлеровых углов (Rz*Ry*Rx).
  • collide_box — SAT по 6 face-осям и 9 cross-product осям с tie-break в пользу face при |overlap_a − overlap_b| < 1e-3.
  • box_manifold — клиппинг incident face четырьмя боковыми плоскостями reference face (Sutherland-Hodgman). Результат сводится в ОДИН контакт в центре клипа — чтобы плоская грань не давала паразитного крутящего момента.
  • edge_contact — ближайшие точки двух рёбер, fallback если face-контакта нет.
  • collide_sphere_box — closest point в box локально, возвращает нормаль из box к sphere; в collide3 нормаль флипается в зависимости от того, кто «a».
  • prepare_contact3 — кросс-произведения r×n для эффективной массы, накопления, bias с кэпом.
  • clamp_body_motion — safety cap на скорость/угловую скорость в конце шага (не внутри solver'а — комментарий объясняет: clamp во время итераций ломает угловую часть импульса).
  • solve_contact3 — накопление импульса по нормали (normal_accum), friction с накоплением и верхней границей по c->normal_accum.
  • sdph3_step — интеграция → broadphase → wake-on-collision (если активное тело наезжает на спящее — спящее просыпается до сборки контактов) → solver → positional correction (кэп 0.2/step) → bounds → clamp → sleep.

Замечания и потенциальные проблемы

⚠️ Реальные баги

audio/audio.c — опечатка в макросе ALSA
#define A_UNLOCK() pthread_unlock(&g_lock) — должно быть pthread_mutex_unlock. На Linux с ALSA не соберётся.
physics/physics2d.c — sdph2_energy
e += 0.5f * b->inv_mass > 0.0f ? ... : 0.0f; — приоритет операторов неверный; условие случайно истинно при inv_mass>0.

ℹ️ Ограничения дизайна

  • physics2d vs physics3d: 3D накапливает импульсы, 2D — нет.
  • audio: master volume читается вне lock в sdge_audio_mix.
  • gltf: только buffer 0; нет morph targets, sparse, Draco, base64-URI, текстур.
  • font: растризуются коды 32..255 — кириллица (≥ 0x400) не поддержана.
  • font.c (TrueType composite): компоненты с трансформацией (scale/2×2) пока игнорируются.
  • window.c (X11): глобальный g_wm_delete_atom на все Display.
  • mesh: только mode 4 (triangles).
  • json.h: SDJ_MAX_TOKENS=4096 — большие glTF без увеличения лимита не грузятся.

Чек-лист перед релизом

  • Исправить pthread_unlock → pthread_mutex_unlock.
  • Почистить sdph2_energy.
  • Добавить накопление импульсов в 2D-солвер.
  • Читать master под локом один раз в начале sdge_audio_mix.
  • Реализовать трансформации в composite-глифах TrueType (или задокументировать ограничение).
