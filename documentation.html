Silver Diamond Game Engine

Небольшой игровой движок на C99: окно и ввод, PBR-lite рендер, glTF/GLB со скелетной анимацией, текстуры, шрифты, GUI, пространственный звук, физика 2D/3D и менеджер сцен. Всё ядро собирается в одну динамическую библиотеку, а игра линкуется с публичным C-API.

C99 OpenGL 3.3+ Windows / Linux glTF 2.0 + GLB SDK: API/include

Введение #

Silver Diamond — «батарейки в комплекте»: один заголовок <sdge.h> подключает все модули, а игра не трогает OpenGL напрямую. Рендерер, загрузчики, GUI и физика живут внутри sdge.dll / libsdge.so.

Рендер

Один forward-шейдер: PBR-lite, ambient + sun + до 8 точечных источников, 5 текстурных слотов, alpha-режимы, скининг.

Контент

glTF 2.0 / GLB, PNG/JPG/TGA/BMP/HDR через stb_image, TTF/OTF шрифты, WAV и MP3.

Логика

Твёрдые тела 2D и 3D (импульсный решатель), сцены с плавными переходами, пространственный звук.

Инструменты

Редактор сцен с иерархией, гизмо, наложением текстур и экспортом в glTF.

Как читать документацию

  • Разделы идут от простого к сложному; каждый содержит готовые фрагменты кода.
  • Код в примерах предполагает #include <sdge.h> и подключённый SDK.
  • Все функции с префиксом sdge_ — высокоуровневые, sdgr_ — рендерер, sdga_ — ассеты, sdph2_/sdph3_ — физика, sdui_ — 2D-рендер.

Установка и сборка #

Требования

  • Компилятор C99: MinGW GCC (Windows), GCC или Clang (Linux).
  • Python 3.8+ — только для сборки движка (build.py).
  • OpenGL 3.3+ и системные библиотеки окна: opengl32, gdi32, user32, winmm на Windows; libGL, libX11, опционально libasound на Linux.

Результат сборки раскладывается по платформе и варианту:

SDK для игры

Команда python build.py sdk создаёт:

  • API/include/ — публичные заголовки (включая sdge.h);
  • API/lib/<platform>/<variant>/ — libsdge.a + sdge.dll (Windows) или libsdge.so (Linux).
Важно Игра включает только API/include и линкуется с библиотекой из API/lib. Внутренние заголовки из core/ для игры не нужны.

Что нового в загрузчике glTF

В этой версии исправлена загрузка больших скачанных моделей: JSON-парсер больше не ограничен 4096 токенами, поддерживает UTF-8 BOM, несколько буферов, percent-encoded URI (%20), нормализованные целые accessor'ы, а также терпимо относится к extensionsRequired.

Первая игра #

Ниже — минимальный, но полноценный каркас: окно, 3D-камера, освещение, загрузка модели с анимацией и простая GUI-надпись. Сохраните как src/main.c.

src/main.c
#include <sdge.h>
#include <stdio.h>

typedef struct {
    sdge_window *window;
    int width, height;
    int running;

    sdge_camera3d camera;
    sdge_model *model;
    sdge_gui *gui;
    sdge_gui_label fps_label;

    double last_time;
} game;

static game g;

static void on_key(sdge_window *w, int key, int scancode, int action, int mods) {
    (void)w; (void)scancode; (void)mods;
    if (action != SDGE_PRESS) return;

    if (key == SDGE_KEY_ESCAPE) g.running = 0;

    if (g.model && key >= SDGE_KEY_1 && key <= SDGE_KEY_9) {
        int index = key - SDGE_KEY_1;
        if (index < sdge_model_anim_count(g.model))
            sdge_model_play(g.model, index, 1);
    }
}

static void on_resize(sdge_window *w, int width, int height) {
    (void)w; (void)width; (void)height;
    sdge_get_framebuffer_size(g.window, &g.width, &g.height);
    sdge_camera3d_set_aspect(&g.camera,
        (float)g.width / (float)(g.height ? g.height : 1));
}

int main(void) {
    if (!sdge_init()) {
        fprintf(stderr, "engine init failed\n");
        return 1;
    }

    sdge_window_hint(SDGE_VSYNC, 1);
    sdge_window_hint(SDGE_RESIZABLE, 1);

    g.window = sdge_create_window(1280, 720, "My Game", NULL);
    if (!g.window) {
        sdge_terminate();
        return 1;
    }

    sdge_show_window(g.window);
    sdge_make_context_current(g.window);
    sdge_get_framebuffer_size(g.window, &g.width, &g.height);

    sdge_set_key_callback(g.window, on_key);
    sdge_set_window_size_callback(g.window, on_resize);

    if (sdgr_init() != 0) {
        fprintf(stderr, "renderer init failed\n");
        sdge_destroy_window(g.window);
        sdge_terminate();
        return 1;
    }
    if (sdui_init() != 0) {
        fprintf(stderr, "UI init failed\n");
        sdgr_shutdown();
        sdge_destroy_window(g.window);
        sdge_terminate();
        return 1;
    }

    g.gui = sdge_gui_create();
    sdge_gui_label_init(&g.fps_label, 16.0f, 16.0f, 260.0f, 24.0f,
                        "FPS: --", 16.0f,
                        (float[]){ 1.0f, 1.0f, 1.0f, 1.0f });
    sdge_gui_add(g.gui, &g.fps_label.base);

    /* модель должна грузиться после создания GL-контекста */
    g.model = sdge_model_load("assets/character.glb");
    if (g.model && sdge_model_anim_count(g.model) > 0)
        sdge_model_play(g.model, 0, 1);

    sdge_camera3d_init(&g.camera, 50.0f,
        (float)g.width / (float)(g.height ? g.height : 1), 0.05f, 500.0f);
    {
        float center[3] = { 0.0f, 1.0f, 0.0f };
        sdge_camera3d_orbit(&g.camera, center, 4.0f, 0.6f, 0.25f);
    }

    const float clear[4]   = { 0.08f, 0.09f, 0.11f, 1.0f };
    const float sun_dir[3] = { -0.4f, -1.0f, -0.3f };
    const float sun_col[3] = { 1.0f, 0.95f, 0.88f };

    g.running = 1;
    g.last_time = sdge_get_time();

    while (g.running && !sdge_window_should_close(g.window)) {
        sdge_poll_events();

        double now = sdge_get_time();
        float dt = (float)(now - g.last_time);
        g.last_time = now;
        if (dt > 0.1f) dt = 0.1f;          /* защита от длинных пауз */

        if (g.model) sdge_model_advance(g.model, dt);
        sdge_camera3d_update(&g.camera);

        sdge_get_framebuffer_size(g.window, &g.width, &g.height);
        sdgr_resize(g.width, g.height);
        sdgr_begin_frame(clear);
        sdgr_set_camera(g.camera.view, g.camera.proj, g.camera.pos);
        sdgr_set_ambient(0.25f, 0.27f, 0.32f);
        sdgr_set_sun(sun_dir, sun_col, 2.2f);
        if (g.model) sdge_model_draw(g.model, NULL);
        sdgr_end_frame();

        char fps[64];
        snprintf(fps, sizeof(fps), "FPS: %.0f",
                 dt > 0.0f ? 1.0f / dt : 0.0f);
        sdge_gui_label_set_text(&g.fps_label, fps);

        sdge_gui_begin(g.gui, g.width, g.height);
        sdge_gui_draw(g.gui);
        sdge_gui_end(g.gui);

        sdge_swap_buffers(g.window);
    }

    if (g.model) sdge_model_destroy(g.model);
    sdge_gui_destroy(g.gui);
    sdui_shutdown();
    sdgr_shutdown();
    sdge_destroy_window(g.window);
    sdge_terminate();
    return 0;
}
Порядок инициализации sdge_init() → окно → sdge_make_context_current() → sdgr_init() → sdui_init() → загрузка моделей и текстур. Загрузка модели и загрузка текстуры на GPU требуют текущего GL-контекста.

Главный цикл и время #

Кадр всегда состоит из одних и тех же шагов:

  1. sdge_poll_events() — забрать события ОС (ввод, ресайз, закрытие).
  2. Посчитать dt по sdge_get_time() и ограничить его (например, 0.1f).
  3. Обновить игровую логику: анимации, физику, управление.
  4. sdge_camera3d_update() — пересчитать view/proj/frustum.
  5. sdgr_resize() → sdgr_begin_frame() → камера/свет → рисование → sdgr_end_frame().
  6. GUI: sdge_gui_begin() → sdge_gui_draw() → sdge_gui_end().
  7. sdge_swap_buffers() — показать кадр.

Стабильный шаг физики

Физику лучше обновлять фиксированными шагами, иначе поведение зависит от FPS. Простой аккумулятор: 

const float STEP = 1.0f / 60.0f;
float accumulator = 0.0f;

/* в каждом кадре: */
accumulator += dt;
if (accumulator > 0.25f) accumulator = 0.25f;   /* не копим бесконечно */
while (accumulator >= STEP) {
    sdph3_step(world, STEP);
    accumulator -= STEP;
}
Совет Для интерполяции рендера между шагами физики храните предыдущую и текущую трансформации тела и смешивайте их с accumulator / STEP.

Свои шейдеры #

Движок содержит небольшой собственный язык шейдеров (файлы .sdshader). Это не «сырой» GLSL: программа транслируется в готовую пару GLSL 330 vertex/fragment, которая использует тот же скелетный трансформ, материалы, текстуры, нормал-мапы и освещение, что и встроенный PBR-проход. Игре не нужно подключать glad или знать про OpenGL.

Минимальный шейдер выглядит так:

shader glow {
    uniform float intensity;

    vertex {
        position.y += sin(time + position.x * 4.0) * 0.03;
    }

    fragment {
        vec3 lit = pbrLighting(normal, albedo, metallic, roughness);
        color.rgb = mix(lit, vec3(0.2, 0.8, 1.0), intensity);
        color.a   = baseColor.a;
    }
}

Обёртка shader имя { ... } необязательна. Если блок fragment не указан, весь код верхнего уровня считается фрагментным. Пустой файл даёт обычный PBR-рендер.

Структура программы

ЧастьОписание
uniform тип имя;Пользовательский uniform. Объявляется в начале, до блоков vertex/fragment.
vertex { ... }Необязательный блок: меняет position, normal, uv, uv1 до скиннинга и проекции.
fragment { ... }Необязательный блок: вычисляет итоговый color.
код верхнего уровняЕсли блоков нет — это фрагментный код.

Поддерживаются комментарии // ... и /* ... */, числа с плавающей точкой (1.0, .5, 1e-3), логические true/false, операторы + - * / %, сравнения < <= > >= == !=, логические && || !, присваивания = += -= *= /=, а также if / else. Строки, массивы, структуры, циклы, пользовательские функции и препроцессор не поддерживаются.

Типы и объявления

uniform float time_scale;     /* float, int, bool, vec2, vec3, vec4,
                                 sampler2D                              */

Имена переменных объявляются в области видимости блока. Повторное объявление и имена встроенных переменных/функций запрещены. Пишите вещественные литералы с точкой: 1.0, а не 1.

Ограничения

  • Шейдер меняет только position/normal/uv в вершинном блоке и итоговый color во фрагментном. Заменить скиннинг, проекцию или PBR-пайплайн целиком нельзя.
  • Нет пользовательских функций, циклов, массивов, структур, in/out-переменных между стадиями и препроцессора.
  • Uniform-ы объявляются до блоков кода; тип при вызове сеттера должен совпадать (int и bool взаимозаменяемы).
  • Вершинный блок должен идти до фрагментного. discard/return — только во фрагменте.
  • Изменение normal в вершинном блоке не пересчитывает касательные и normal map автоматически.
  • Ошибки GLSL (например, несовпадение типов аргументов) возвращаются драйвером в error; исходный GLSL доступен для отладки.

sdge_model — высокоуровневый 3D-объект: загружает .glb или .gltf (+ внешние .bin и текстуры), загружает меши на GPU, владеет анимационными плеерами и рисует всю иерархию узлов со скинингом и отсечением.

Ассеты, арены и файлы #

sdga_arena — блочный аллокатор: выделения никогда не перемещаются, поэтому указатели остаются валидными при росте арены. Одна модель glTF живёт в одной арене: загрузка — несколько malloc, освобождение — один вызов. 

sdga_arena arena;

printf("used: %zu bytes in %zu blocks\n",
       sdga_arena_used(&arena), arena.block_count);

sdga_arena_destroy(&arena);   /* освобождает всё сразу */
unsigned char *bytes;
size_t size;
if (sdga_read_file("assets/data.bin", &bytes, &size) == 0) {
    /* ... */

    src/main.c -o build/MyGame.exe ^
    sdk/lib/windows/release/libsdge.a

Для отладки замените release на debug и добавьте -g.

gcc -std=gnu99 -O2 -DSDGE_USE_DLL -I sdk/include \
    src/main.c -o build/MyGame \
    -Lsdk/lib/linux/release -lsdge -Wl,-rpath,'$ORIGIN' -lm

cp sdk/lib/linux/release/libsdge.so build/
cp -r assets build/assets

Что положить рядом с exe

  • sdge.dll — обязательно (Windows);
  • libsdge.so — обязательно (Linux, если нет системной установки);
  • папка assets/ — модели, текстуры, звуки, шрифты;
  • для MinGW-сборки иногда нужны runtime-DLL компилятора (libgcc_s_seh-1.dll, libwinpthread-1.dll), если они не входят в систему.
Совет Используйте SDGE_USE_DLL при компиляции игры. Без него заголовки не помечают функции как dllimport, и линковка на Windows может выбрать неверный путь.

  • Не создавайте и не уничтожайте модели/текстуры каждый кадр — кэшируйте.

Траблшутинг #

Модель не загружается

  • Проверьте путь: он относителен рабочей директории, а не exe.
  • GL-контекст должен быть создан и текущим до sdge_model_load().
  • Сообщение gltf: bad JSON в старых версиях означало лимит токенов; обновите движок — теперь JSON считается точно и буфер выделяется динамически.
  • Если в консоли requires compressed geometry (KHR_draco_mesh_compression) — геометрия пустая; пересохраните модель без Draco.
  • Для .gltf с внешними файлами убедитесь, что .bin и текстуры лежат рядом или по указанным относительным путям.

Чёрный экран

  • Вызван ли sdgr_set_camera() до рисования?
  • Есть ли sdgr_begin_frame() / sdgr_end_frame()?
  • Камера не смотрит в пустоту: проверьте center, dist, znear/zfar.
  • Есть ли свет? Без ambient/sun модель может быть почти чёрной.
  • Модель может быть очень большой или очень маленькой — впишите её в кадр по bounding sphere.

GUI не реагирует

  • Проброшены ли события окна в sdge_gui_*?
  • Виджет добавлен через sdge_gui_add()?
  • base.visible и base.enabled равны 1?
  • Виджеты рисуются после 3D-сцены и после sdgr_end_frame()?

Текст не виден

  • sdui_init() вызван после создания GL-контекста?
  • Шрифт загружен и передан в sdui_set_font(); не освобождён ли он раньше времени?
  • Цвет текста не совпадает с фоном и alpha > 0?

Ошибка линковки

  • undefined reference to sdge_* — добавьте -DSDGE_USE_DLL и import-библиотеку libsdge.a; порядок: сначала исходники/объекты, потом библиотека.
  • На Linux — -lsdge и -lm, а также -Wl,-rpath,'$ORIGIN'.
  • При запуске «sdge.dll not found» — положите DLL рядом с exe или в PATH.

Звука нет

  • sdge_audio_has_device() — есть ли устройство (в WSL/CI его может не быть).
  • Проверьте sdge_audio_get_master_volume() и громкость источника.
  • Для 3D-источника вызовите sdge_audio_source_set_spatial(s, 1) и задайте позицию слушателя.

Физика «проваливается»

  • Пол/стены должны быть статическими (mass <= 0) и достаточно большими.
  • Увеличьте sdph3_world_set_iterations(w, 12..20).
  • Не используйте слишком большой dt: держите 1/60 и фиксированный шаг.
  • Проверьте sdph3_world_set_bounds(): границы могут отбрасывать тела назад.
